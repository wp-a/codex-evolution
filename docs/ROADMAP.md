# Product direction and release plan

The distinctive loop is **evidence → less friction → reusable workflow**, not a prettier token counter. GitHub popularity is uncertain; clear value, honest measurements, easy installation and useful examples are within the project's control.

## v0.1, implemented

Local history adapters; interactive heatmaps and evidence; monthly request-signal timeline; conservative plan/AGENTS/Skill audit; proposed diffs; workflow candidates and skill drafts; complete prompt workbench; reports/share cards; reviewed handoff packets; optional tool-free Responses API; standard-library CLI/server; tests, documentation and CI configuration.

## v0.1.1, growth dossier integration

Extend the existing analytics → reports → web path with a seven-signal change ledger, pooled early/middle/late denominators, a six-row monthly phase matrix, heuristic observation anchors, cautious readout, optional four-line protocol and keep/avoid audit. Short windows explain insufficient coverage. Export the same aggregate dossier in Markdown, standalone HTML and JSON, with synthetic demo data kept separate from personal history.

## Next: compatibility before more dashboards

Collect consented, **synthetic/minimized** fixtures representing actual Codex versions. Expose explicit per-adapter coverage. Improve overlapping metadata and malformed-history diagnostics. Add targeted tests for conditional English/Chinese audit language before claiming semantic completeness. Add a full English UI, accessible chart summaries and a static interactive demo mode only after preserving data isolation.

## Then: measured improvements, not capability scores

Add an opt-in local change journal: what instruction changed, what outcome the user actually observed, which task class it affected. Compare comparable tasks before/after; separate interruption counts from genuinely required approvals. Track unresolved findings and accepted/rejected recommendations without automatically applying changes. Evaluate skill candidates against user-confirmed outcomes rather than repetition alone.

## Optional later integrations

A reviewed local `codex exec` adapter with clear approval/timeout behavior; more providers; incremental imports/file watching; bounded batch semantic summaries with complete coverage reporting. None is represented as implemented in v0.1. No need for multi-agent orchestration, microservices, an account system, vector database or cloud storage merely to build this local utility.

## Public release package

The public repository is `wp-a/codex-evolution`, with v0.1.1 source, wheel, and a [media kit](marketing/README.md). The MIT license and independent-project attribution remain visible. The kit includes eight images composed from real synthetic-demo screenshots and [launch copy](launch/LAUNCH_COPY.md). No PyPI publication or public app hosting is included; the service runs locally. Future release packages should keep source, screenshots, test evidence and known limits in sync.

A short product demonstration can show three moments: click a statistic to reveal its message evidence; identify a blocking instruction while retaining deployment approval; export a supported workflow as a review draft. The PNG collaboration card and standalone HTML report are deliberate sharing surfaces, but they must never expose raw private histories.
