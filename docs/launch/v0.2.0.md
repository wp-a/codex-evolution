# Codex Evolution v0.2.0

Codex Evolution now connects recorded Token usage with a practical improvement workspace. Import supported local history, inspect the usage you actually have records for, prepare the next task and keep a note of what helped.

## What's new

- **Token usage:** input/output totals, cache/reasoning subsets, monthly views, recorded model context, high-usage threads and aggregate JSON download. Explicit per-response events are deduplicated across reimports and copies. Legacy cumulative snapshots remain a separate reference view.
- **Improvement workspace:** editable goal/context/scope/success brief, suggestions tied to the current history, browser-local trial notes, acceptance criteria and user-recorded outcomes. Demo and personal notes stay separate.
- **Complete product documentation:** visible screenshots, detailed introductions and practical usage instructions. Author posting drafts have moved out of the product repository. The author relay link remains in its own section.

The application does not infer account totals, subscription quotas, prices, bills or productivity scores. Missing usage stays unknown. Original history remains read-only; the local runtime has no third-party dependencies.

## Run locally

Requires Python 3.10 or later. Install the wheel or download the source archive and run:

```bash
python -m pip install .
python -m codex_evolution demo --open
```

Choose **Token 用量** or **改进工作台** from the sidebar. The default local address is `http://127.0.0.1:8765`. Use the same browser and address to return to saved improvement notes; export JSON to retain a backup.

See [usage data definitions](../USAGE_DATA.md), the [improvement guide](../IMPROVEMENT.md) and the [full usage guide](../USAGE.md).

## Validation

104 core tests cover parsing, deduplication, filters, export privacy, storage, HTTP routes and existing reports. Browser checks exercise the new usage and journal flows, reload persistence, dataset isolation, failure recovery, exports and layouts from 320 to 1512 pixels, alongside the existing application smoke checks. All development records are synthetic; no paid model request or personal-history import is used for validation.
